## СУТЬ ПРОЕКТУ В ОДНОМУ РЕЧЕННІ

Workflo.space — це цифровий офіс команди автоматизаторів, де бізнес знаходить рішення своїх проблем, бачить докази через кейси і отримує зручний інструмент для роботи разом.

---

## ДВІ CORE КОНЦЕПЦІЇ

### Концепція 1: Ми вирішуємо бізнес-проблеми

Позиціонування — не технологічне, а проблемно-орієнтоване.

**Ми не продаємо "Node.js розробку" або "DevOps".**
Ми продаємо:

- Час який повертається команді замість рутини
- Процеси які не ламаються при масштабуванні
- Системи які спілкуються між собою без людини посередині
- Рішення прийняті на основі даних а не відчуттів

Клієнт не знає що таке CI/CD. Але він знає що його менеджер витрачає 3 години на день на copy-paste. Ми говоримо його мовою.

**Технології — це інструменти, не продукт.** Вони є на окремій сторінці /stack для тих хто хоче перевірити компетентність. На головній — тільки бізнес-результати.

### Концепція 2: Команда з великим досвідом, доведеним через кейси

Довіра будується не через перелік технологій, а через докази реальної роботи.

- Кожен кейс = вирішена бізнес-проблема з конкретними цифрами
- Кейси показують різноманітність задач і глибину розуміння бізнесу
- Команда представлена через свій досвід і спеціалізацію, не посади
- AI-асистований пайплайн для генерації кейсів (деталі нижче)

## КЛІЄНТООРІЄНТОВАНІСТЬ ЯК ОСНОВА

Все — від кнопки до архітектури бази даних — вирішується через одне питання:
**"Як це зручніше для клієнта?"**

Прояви на практиці:

- Жодного жаргону на головній сторінці
- Клієнт бачить статус своєї задачі в реальному часі без дзвінків
- Сповіщення приходять там де клієнту зручно (email або Telegram)
- Портал мінімалістичний — клієнт робить що хоче за 3 кліки
- Ціна і терміни видимі одразу, без "ми вам передзвонимо"

---

## СТРУКТУРА УТРИМАННЯ КЛІЄНТА (FUNNEL)

Мета: тримати клієнта в контакті з брендом якомога довше, на кожному етапі давати цінність.

```
ЗАЛУЧЕННЯ
    │
    ▼
[Лендінг] — SEO + бізнес-посил → клієнт впізнає свою проблему
    │
    ▼
[Кейси] — "О, вони вирішували схоже у схожого бізнесу" → довіра
    │
    ▼
[Контакт] — форма або Telegram → перший дотик
    │
    ▼
[Портал] — зручна робота разом → прив'язаність через зручність
    │
    ▼
[Telegram канал] — корисний контент між задачами → не забуває про нас
    │
    ▼
[Нова задача] — наступний проект → повторний продаж
    │
    ▼
[Абонплата] — постійна цінність → довгострокові відносини
```

На кожному кроці воронки клієнт отримує щось корисне. Немає порожніх точок контакту.

## ПРОДУКТОВА КАРТА

### 1. Лендінг (workflo.space)

**Головна сторінка:**

- Hero: бізнес-посил, маскот, CTA
- "Які проблеми ми вирішуємо" (6 бізнес-ситуацій, не технологій)
- Як ми працюємо (3 кроки)
- Вибрані кейси (3-4 найкращих)
- Telegram канал preview
- Моделі співпраці (разово / абонплата)
- FAQ
- CTA

**Окремі сторінки:**

- `/cases` — всі кейси з фільтрами
- `/cases/[slug]` — деталь кейсу (SEO-сторінка)
- `/team` — команда з досвідом і спеціалізацією
- `/stack` — технологічний стек (для технічних)
- `/blog` — статті (Phase 2+)

**Двомовність:** UA (основна) + EN (для міжнародного ринку)

### 2. Клієнтський портал (portal.workflo.space)

**MVP функціонал:**

- Реєстрація / логін
- Створити задачу (назва, опис, тип, файли)
- Дивитись статус задачі
- Чат по задачі в реальному часі
- Сповіщення: email + Telegram (на вибір клієнта)

**Адмін функціонал (MVP):**

- Всі задачі всіх клієнтів
- Встановити ціну задачі
- Змінити статус
- Внутрішні коментарі (клієнт не бачить)

**Типи послуг:**

- Разова задача — оцінка + підтвердження + виконання
- Абонплата — фіксовані X годин/місяць на задачі та підтримку

**Без Stripe в MVP** — оплата офлайн, Stripe додається в Phase 2.

**Нотифікації в MVP:**

- Email при зміні статусу задачі
- Email при новому повідомленні в чаті
- Telegram (якщо клієнт прив'язав аккаунт)

### 3. Telegram канал

- Скорочені версії кейсів
- Думки про автоматизацію
- Корисні спостереження з реальних проектів
- Без реклами і води
- Автоматична публікація при виході кейсу на лендінг

### 4. Корпоративна пошта

- Домен: @workflo.space
- Формат: name@workflo.space
- Для команди і клієнтської комунікації
- Варіанти: Google Workspace, Fastmail, або self-hosted (Mailcow на Hetzner)
- Рекомендація: **Google Workspace** — зручно, надійно, знайоме клієнтам

## МАСКОТ

**Autocat** — кіт-автоматизатор.

Чому кіт (а не сова): сова вже використовується в існуючих продуктах команди — розмиває бренд. Кіт вписується в tech-культуру, має гнучкий характер, додає легкий гумор.

Стани маскота:

- Default: дивиться в термінал
- Processing: очі як loading spinner
- Done: задоволений, thumbs up
- Error: перевернутий з `500` над головою
- Sleep: один eye відкрите — "watchdog mode"

Використовується: лендінг (hero), портал (login, empty states, success), email шаблони, Telegram канал як аватар.

- Geist — заголовки (підтримує кирилицю)

**Dark mode** за замовчуванням, light mode як опція.

## ТЕХНІЧНА АРХІТЕКТУРА (попередня)

```
workflo.space/              ← Монорепо (Turborepo + pnpm)
├── apps/
│   ├── landing/            ← Next.js 15 (SSR/SSG для SEO)
│   ├── portal/             ← React Vite SPA (клієнтська зона)
│   ├── api/                ← Node.js Fastify (бекенд порталу)
│   └── bot/                ← Telegram bot (grammY)
└── packages/
    ├── ui/                 ← Shared компоненти + CatMascot
    ├── db/                 ← ORM + міграції (Drizzle або Prisma — TBD)
    └── types/              ← Shared TypeScript типи
```

**Хостинг:** Власний сервер Hetzner + Docker Compose + Traefik (вже налаштований)

**БД:** PostgreSQL в Docker

**Realtime чат:** Server-Sent Events (SSE) + PostgreSQL LISTEN/NOTIFY

**CI/CD:** GitHub Actions → SSH → docker compose pull → up

**Dev/Prod:**

- `main` → workflo.space (production)
- `dev` → dev.workflo.space (staging)
- `feature/*` → preview deploy (manual або auto через Actions)

**Два окремих середовища БД:** production і staging — ніколи не тестуємо на prod.

## AI ПАЙПЛАЙН ДЛЯ КЕЙСІВ

```
1. Заповнюємо форму в адмінці:
   - Тип бізнесу клієнта (анонімно)
   - Проблема: що робили вручну, скільки часу/людей
   - Рішення: що зробили (без технічного жаргону)
   - Результат: конкретні цифри

2. API → Claude генерує кейс (600-800 слів, UA + EN)
   Фокус: бізнес-проблема і результат, не технічний опис

3. Адмін переглядає, редагує, публікує

4. Next.js ISR revalidation → сторінка оновлюється без rebuild

5. Webhook → Telegram бот публікує скорочену версію в канал
```

## MVP — ЩО ТОЧНО РОБИМО НА СТАРТІ

### Лендінг MVP:

- [ ] Всі секції головної з реальним контентом
- [ ] Мінімум 3 кейси опублікованих
- [ ] UA + EN версії
- [ ] SEO: metadata, sitemap, hreflang, schema markup
- [ ] Контактна форма (email)
- [ ] Сторінки: /cases, /team, /stack

### Портал MVP:

- [ ] Реєстрація / логін
- [ ] Клієнт: створити задачу, дивитись список, деталь задачі
- [ ] Чат по задачі (realtime SSE)
- [ ] Сповіщення: email + Telegram (опція)
- [ ] Адмін: всі задачі, ціна, статус, внутрішні коментарі

### Інфраструктура MVP:

- [ ] Монорепо налаштований
- [ ] Docker Compose на Hetzner
- [ ] CI/CD: GitHub Actions → Hetzner
- [ ] Dev і prod середовища розділені
- [ ] Корпоративна пошта @workflo.space

### НЕ в MVP (але архітектурно заготовлено):

- Stripe / онлайн оплати
- Оператори і розподіл задач
- Phone verification
- Invoice PDF
- Аналітика для клієнта
- /blog секція
