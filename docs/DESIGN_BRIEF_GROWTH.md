## A. LEADS (модуль 26) — Workspace

### A1. `/leads` — Канбан лідів

- **Призначення:** воронка потенційних клієнтів; вести лід по етапах.
- **Макет:** горизонтальний канбан (колонки = stages). Зверху — toolbar (перемикач воронки, фільтри, пошук, «+ Лід»).
- **Елементи:** колонка (назва stage + колір-смужка + лічильник + сума?); картка ліда (імʼя/компанія, **source-badge** з іконкою каналу: сайт/Telegram/IG/TikTok/FB/WhatsApp, контакт, час, аватар assignee, пріоритет). Drag-handle.
- **Стани:** порожня колонка (placeholder), drag-over (підсвітка), won/lost-колонки (приглушені), фільтр-активний.
- **Флоу:** drag картки між колонками → зміна stage; won/lost → візуально завершено; клік → A2; «+ Лід» → модалка створення (manual).

### A2. `/leads/:id` — Картка ліда

- **Макет:** 2 колонки. Ліворуч — контакт+атрибуція (source, utm/handle, дата, поточний stage-селектор, assignee-селектор, пріоритет). Праворуч — **activity-timeline** (нотатки/зміни статусу/inbound) + поле нової нотатки.
- **Ключова дія:** кнопка **«Зробити клієнтом»** (конверсія → створює компанію; підтвердження-модалка з email).
- **Стани:** converted (бейдж + лінк на клієнта), lost (причина).

### A3. `/settings/leads/pipelines` — Налаштування воронки

- CRUD воронок + етапів: список stages з drag-order, інлайн-редагування (назва/колір/тип open|won|lost), кілька воронок, мітка `isDefault`. Прев'ю канбану.

## B. INTEGRATIONS (модуль 27) — Workspace

### B1. `/settings/integrations` — хаб (вкладки)

- **Вкладка «API-ключі»:** таблиця (назва/scopes/lastUsed/status); «Створити» → модалка (назва+scopes) → показ ключа **рівно раз** (copy + попередження); revoke.
- **Вкладка «Форма на сайт» (inbound):** обраний ключ + поле «дозволені домени» + **готовий сніпет** (copy: `<form>`/`fetch` приклад на `/v1/leads`) + журнал останніх отриманих лідів (час/джерело/статус).
- **Вкладка «Канали»:** картки каналів (Telegram ✅, Instagram/Facebook/WhatsApp/TikTok — «Підключити» через OAuth/токени), статус-бейдж connected/off.
- **Вкладка «Webhooks» (outbound):** список endpoint'ів (url/події/active); «Додати» (url + чек-лист подій order/payment/lead + secret); **журнал доставки** (`WebhookDelivery`: подія/статус/код/спроби) + кнопка «Тест».
- **Стани:** ключ-показ-раз (нескопійований/скопійований), канал connecting/error, webhook failing (червоний бейдж), delivery dead (DLQ).

## C. CLIENT MANAGEMENT (модуль 28) — Workspace

### C1. `/clients` — Список клієнтів

- Таблиця: назва, LTV/totalSpent, loyalty-тір (бейдж), к-сть замовлень, статус (active/deactivated), останній контакт. Фільтри/пошук/сорт. «+ Клієнт».

### C2. `/clients/:id` — Картка клієнта

- **Макет:** хедер (назва + статус + швидкі дії: редагувати/деактивувати) + вкладки: **Інфо** (редагована картка: назва/нотатки/валюта/мова/tierOverride/реквізити), **Команда** (члени клієнта + ролі), **Замовлення**, **Білінг** (рахунки/борг), **Credentials** (17), **Джерело** (lead-атрибуція).
- **Вкладка «Команда»:** таблиця членів (імʼя/email/роль/останній вхід) + дії: «Запросити», «Змінити роль», «Зняти», **«Скинути пароль»**.

### C3. Модалка **Admin reset-password** (рішення: обидва)

- Вибір режиму: **«Надіслати лінк»** (за замовч. — юзер отримає лист) / **«Тимчасовий пароль»** (показати раз owner'у + примус зміни). Попередження «всі сесії юзера завершаться». Після temp — показ пароля **рівно раз** (copy).

### C4. Деактивація/офбординг

- Модалка-підтвердження деактивації (read-only пояснення). «Експорт даних клієнта» (GDPR) — генерує архів.

## D. SUPPORT (модуль 29)

### D1. Portal — `/support`, `/support/new`, `/support/:id`

- **Список «Мої звернення»:** картки (subject, статус-бейдж, остання активність, непрочитані). «Нове звернення».
- **Нове:** subject + категорія + повідомлення + файли.
- **Тред:** повідомлення (клієнт/команда), поле відповіді, статус зверху. Лише public (internal-нотатки невидимі).

### D2. Workspace — `/support` (черга) + `/support/:id`

- **Черга:** таблиця/канбан тікетів (subject, клієнт, пріоритет, статус, assignee, SLA-таймер). Фільтри (status/priority/assignee/category).
- **Тікет:** тред (з **internal-нотатками**, візуально відмінні — жовтий фон), панель дій (статус open/pending/resolved/closed, пріоритет, призначення, категорія), кнопка **«Створити замовлення з тікета»**.
- Інтеграція в **chat-hub** (18) — тікети поряд із order-чатами.

## E. SaaS WHITE-LABEL CONFIG (SAAS_CONFIG.md) — Workspace + Platform

### E1. `/settings/branding`

- Лого (світле/темне), favicon, назва, accent-колір (палітра пресетів + кастом-пікер), тема за замовч., шрифт-пресет. **Лайв-прев'ю** на семпл-компонентах (кнопки/картки/бейджі) — показує, як токени змінюють вигляд.

### E2. `/settings/domain`

- Subdomain (`acme`.workflo.space — валідація унікальності) + custom domain (поле + інструкція CNAME + статус-бейдж верифікації).

### E3. `/settings/landing` — **Landing CMS** (per-agency лендинг)

- Секційний редактор: список секцій (hero/послуги/про-нас/відгуки/контакти) — увімк/вимк + drag-order; форма полів секції; SEO-поля; **прев'ю** + «Опублікувати» (draft/published).

### E4. `/settings/client-portal`

- Welcome-текст/онбординг, перемикачі видимих фіч, контакти підтримки.

### E5. Per-agency **лендинг** (рендериться по домену)

- Брендований маркетинг-сайт агенції (контент із E3, токени з E1). Окремий від платформного `workflo.space`. SEO/ISR.

### E6. Super-admin (платформа, пізніше)

- Список агенцій (план/статус/usage), suspend/resume, impersonate, платформні метрики.

## Примітки для дизайну

- **Усе на `--wf-*` токенах** — жодного hex-хардкоду (white-label вимога).
- Source-іконки лідів (сайт/Telegram/IG/TikTok/FB/WhatsApp) — потрібен консистентний icon-set.
- Канбан (ліди A1, тікети D2) — спільний drag-патерн із order-stages.
- Тред (тікети D, чат 03) — спільний message-thread-компонент + internal-leak візуал.
- Reset-password + revoke-key + suspend — деструктивні дії → confirm-модалки + попередження.
