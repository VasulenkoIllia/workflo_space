# ADR-005: Modular Monolith (НЕ мікросервіси)

**Статус:** Прийнято · **Дата:** 1 червня 2026
**Контекст:** Власник питав, чи варто розділяти систему на мікросервіси для «правильної архітектури на старті». Продукт: одна команда, pre-launch, спершу для власної агенції, SaaS — у кінці. Стек: Turborepo-моноліт (apps/{api,landing,portal,workspace,bot} + packages/\*), Fastify 5 + Prisma + PostgreSQL, single-replica.

---

## Рішення

**Модульний моноліт.** Жодних мікросервісів зараз — і це не близько.

Причини (конкретні, не догматичні):

1. **Домен глибоко транзакційний.** `transitionOrderStatus` робить `order.update` + `activityLog.create` + `enqueueOutbox` в ОДНІЙ Postgres-транзакції. Фінанси (`Payment → PaymentAllocation → ServiceCharge → WalletTransaction`) — інваріант балансу в одній tx. Розділення на сервіси перетворює це на dual-write/saga з компенсаціями — руйнує те, що зараз правильно.
2. **FK-цілісність безкоштовна.** Сотні FK з `onDelete`-каскадами. Мікросервіси її знищують (FK не працюють між БД).
3. **Мікросервіси розвʼязують організаційні (Conway) і масштабні проблеми, яких немає.** Ціна: розподілені транзакції, eventual consistency, service discovery, дубльована observability, мережеві фейли. Виграш до перших десятків платних тенантів — нуль.
4. **Seam'и вже є** (StorageAdapter/PaymentProvider/notify/outbox/LeadSourceAdapter) — майбутня екстракція можлива без «розрізу» зараз (див. ADR-006).

## Тригери перегляду (не дати)

- PDF/відео-рендеринг або AI-генерація блогу починають блокувати event-loop API.
- Bot-навантаження (Telegram) конкурує з API за ресурси.
- Команда виростає до 3+ незалежних потоків, що конфліктують у деплої.
- Перші десятки платних тенантів із незалежними піками.

Жоден тригер зараз не активний.

## Наслідки

- Проста локальна розробка (`docker compose` + `pnpm dev`), транзакційна цілісність, FK.
- Межі модулів тримаємо дисципліною (packages + adapter-seams + `can()`/tenant-guard), не мережею.
- Найбільший ризик стадії — **над-інженерія під виглядом «правильно на старті»**. Найправильніше — простий моноліт із чистими швами, який уже здебільшого є.
