## 🎯 Головний висновок (чесно)

Збудоване — це **міцний, але спрощений фундамент S2-рівня**. Дизайн — це **повноцінний продукт агенції** (~50 пунктів навігації в 13 групах; збудовано ~8 у 5 групах). Розрив **~70% — бекендний** (потрібні нові моделі/ендпойнти), ~30% — **фронтовий** (бекенд готовий, UI заглушка або спрощений).

**Це й була корінна причина:** я брав зрізи «що витримує наявний бекенд» і малював UI під нього, а не під дизайн. Тому екрани систематично виходили простішими, і ти ловив це постфактум.

| Стан екрана                                  | К-сть (приблизно) |
| -------------------------------------------- | ----------------- |
| 🟢 Конформний (збігається з дизайном)        | ~12               |
| 🟠 Частковий (є, але спрощено/IA інша)       | ~18               |
| 🔴 Великий розрив (не той екран / відсутній) | ~16               |

## 📋 Матриця по модулях (ключові розбіжності)

### Замовлення / Задачі / Чат / Час

- 🔴 **Деталь замовлення:** дизайн = 7 табів (Огляд·Чат·Час·Специфікація·Файли·Документи·Activity) + estimate-vs-actual прогрес-бар + floating timer; збудовано = 4 таби (Чат·**Задачі**·Файли·Час) + sidebar-картки. Відсутні Огляд/Специфікація/Документи; зайвий «Задачі».
- 🔴 **Реальний таймер** (старт/стоп, 1 активний/виконавця, floating bar, стоп→коментар) — відсутній; є лише ручні години. `TimeLog` без `startTime/endTime/isActive`. [backend-first]
- 🔴 **Глобальна «Дошка задач»** (`/board`, командні дошки, типи задач, DnD) — маршруту немає; підмінено per-order «Задачі» + order-kanban. [backend-first]
- 🟠 **Специфікація** (spec із time-entries + AI-перепис + надіслати клієнту) — відсутня. [backend-first]
- 🟠 **Чат-ідентичність:** дизайн = аватар + роль («Ілля·workflo» / «Олена (клієнт)») + бульбашки; збудовано = імʼя/«ви». Дані автора вже є. [frontend-only]
- 🟠 **WS `/orders`** дизайн = таблиця-реєстр (+ теги, SLA); збудовано = дефолт-канбан. [frontend-only]
- 🟢 Портал `/orders` список + `/orders/new` + деталь (Чат·Файли·Документи) — конформні.

### Гроші (Білінг / Фінанси / Гаманець / Лояльність / Реферали / Admin-Wallet)

- 🔴 **Портал Гаманець:** дизайн = 2 hero-картки (бонуси+гроші) + «Поповнити» (top-up 25-А) + «Застосувати до рахунку»; збудовано = 3 плоскі плитки. [backend-first — потрібен платіжний провайдер/webhook]
- 🔴 **Лояльність 4-tier vs дизайн 5-tier** (немає `silver`) — розбіжність моделі даних. [backend-first]
- 🟠 **Портал Білінг:** немає табу Recurring (підписки/run-rate/pause); charge-центрично, без №інвойсу/PDF. [backend-first, частково розблоковується з `PortalSummary.projects[]`]
- 🟠 **Реферали** зведено до заглушки vs дизайн-воронка (invited→signed→active→paid) + rich-список. [backend-first]
- 🟠 **Finance Витрати:** немає monthly-eq (MRR), linked-entity, paused/MRR-стат-рядка. [frontend-only — похідні з наявних полів]
- 🟠 **WS Білінг IA:** дизайн = 1 хаб з 6 підтабами; збудовано = окремі маршрути (тіла є). [frontend-only]
- 🟠 **Admin-Wallet деталь:** немає hero-балансів, Refund, live-preview. [partial]
- 🟢 Finance Огляд (donut+chart+CSV), Billing approval-flow + DiscountModal + CreatePaymentModal — конформні/перевершують дизайн.

### Проєкти / Клієнти

- ✅ **Іменування вирішено:** дизайн «Проєкти» === збудоване «Фін-проєкти» (той самий концепт; канон-файл `workspace-project360-list.jsx`). Різниця: дизайн ділить Клієнтські/Внутрішні (build не має `internal`).
- 🔴 **Client 360:** дизайн = 7-таб картка (Огляд·Люди·Проєкти·Фінанси·Документи·**Секрети**·Активність); збудовано = **тонкий список замовлень**. [backend-first — vault, dunning, tags, activity, people-admin]
- 🔴 **Project 360:** дизайн = 8 табів + view-toggle + KPI-hero; збудовано = 4 картки (Білінг·Юр-особа·Маржа·close-cycle). [backend-first для табів; view-toggle+KPI-hero — frontend]
- 🟠 **Клієнти список:** немає «Потребують уваги», LTV/борг/джерело, фільтр-пілюль, create-client. [LTV/борг — backend-first; пошук/пілюлі — frontend]
- 🟢 Project білінг-конфіг + юр-особа + маржа + manual close-cycle — реально backend-backed.

### Маржа / Звіти / Сервіси / Виплати / Команда

- 🔴 **Звіти (`/reports`)** — модуля немає взагалі (дизайн = 6-таб аналітика); є лише headless `GET /reports/pnl`. [backend-first]
- 🔴 **Сервіси-каталог** — інша модель даних: дизайн = dual-axis (cost×bill) + kind/category/makesTask/margin%; збудовано = плоска `{name,price,hours,isRecurring}`. [backend-first — Prisma `Service` однокосний]
- 🔴 **WS `/team` ростер — заглушка, хоча бекенд готовий** (`GET /workspace/team` віддає members+rates). **Найдешевший цінний фікс.** [frontend-only]
- 🟠 **Маржа executor-таб** диверг (немає revenue/margin на виконавця) + zeroCost невидимий. [partial]
- 🟠 **Портал `/team` «Учасники»** ростер+стати — заглушка. [frontend-only]
- 🟠 **Leave/capacity** (`/leave`) — модуля немає. [backend-first]
- 🟢 **Виплати (`/payouts`)** — сильна конформність (UK month-picker, generate, статуси, RateModal).

### Auth / Онбординг / Налаштування / Секрети

- 🔴 **Секрети/Vault** (`portal-secrets`: типові картки, 2FA-reveal, журнал доступу 17-Б) — модуля немає. [backend-first]
- 🔴 **Логін — голий email+password** vs дизайн multi-method (email/phone/magic-link/2FA, caps-lock, лічильник спроб). DB має `OtpToken` enum, але 0 API + немає `Profile.phone`. [backend-first]
- 🔴 **Онбординг — 5-крок візард** (workspace/company/team/channels/done) не збудований. [здебільшого frontend-only]
- 🔴 **Налаштування сплощені:** немає sub-tab; portal-security (phone/2FA/telegram/active-sessions) + WS admin-settings (шаблони/SMTP/брендинг/номенклатура/крони) не збудовані. [backend-first]
- 🟠 **Register** company-крок зведено до `companyName` (дизайн: тип/ЄДРПОУ/slug/валюта/мова). [backend-first]
- 🟢 forgot/reset password — конформні (live-таймер, strength meter).

### Shell / Навігація / Дашборди / Інбокс

- 🔴 **Інбокс/Сповіщення** — повністю не збудовано (portal `/inbox`=Placeholder, WS interface немає маршруту) + admin notif-hub (5 табів). **Найбільша відсутня поверхня.** [backend-first]
- 🔴 **Портал «перемикач компаній» логаутить** — footer = `onClick={logout}`, хоча `user.companies[]` є. Дизайн = `CompanySwitcherPop`. **UX-баг.** [frontend-only]
- 🔴 **WS sidebar IA ≈ 16% дизайну** (8 пунктів vs ~50). Багато — реальні майбутні екрани; нав обрізаний до «що є». [переважно frontend, гейтиться екранами]
- 🟠 **Топбар:** дзвоник-сповіщень — no-op (немає BellDropdown); хлібні крихти не передаються. [partial]
- 🟠 **Sidebar count-badges** відсутні скрізь (UI підтримує, nav не задає). [frontend-only]
- 🟠 **Owner-дашборд** перероблено, не портовано (немає 4 board-slice панелей; додано donut+kanban). [frontend-only]
- 🟢 ⌘K command palette, theme/lang, portal-нав, role-filtering, portal `/`→`/orders` — конформні.

## 🧭 Беклог у двох треках (за залежністю від бекенду)

### Трек F — **frontend-only швидкі перемоги** (бекенд готовий, UI заглушка/спрощений)

Робити ПЕРШИМИ — дешево, видимо, нічого не блокує:

1. **Портал company-switcher логаутить → перемикач компаній** (UX-баг, дані є). ⚡
2. **WS `/team` ростер** (бекенд віддає members+rates). ⚡
3. **Портал `/team` «Учасники» ростер + стати.** ⚡
4. **Чат-ідентичність** (аватар + роль команда/клієнт + бульбашки).
5. **UI виставлення оцінки замовлення** (бекенд `updateOrder` готовий) — розблоковує грошовий ланцюг.
6. **Order «Огляд» таб + estimate-vs-actual бар** (дані є).
7. **Sidebar count-badges** (лічильники з наявних list-ендпойнтів).
8. **Маржа: zeroCost badge/note** + paid progress-bar.
9. **Finance Витрати: monthly-eq (MRR) + linked-entity колонки** (похідні).
10. **Топбар: хлібні крихти.**

### Трек B — **backend-first модулі** (потрібні нові моделі/ендпойнти; планувати як S6+ окремо)

Кожен — повноцінний модуль, не «дотягнути UI»:

- **Інбокс/Сповіщення** (обидва застосунки + admin notif-hub) — найбільша відсутня поверхня.
- **Реальний таймер часу (T2)** — міграція `TimeLog` + start/stop + one-active index + cron + floating-UI.
- **Глобальна «Дошка задач»** — agency-wide task-модель/ендпойнт.
- **Client 360** (7 табів: vault, dunning, tags, activity, people-admin, client-docs).
- **Project 360** (8 табів: team-on-project, retainer/services, contracts, recurring-tasks).
- **Звіти** (6-таб аналітика поверх агрегацій).
- **Секрети/Vault** (encrypted storage + 2FA-reveal + журнал).
- **Сервіси-каталог dual-axis** (cost×bill, kind, makesTask) — Prisma-міграція.
- **Auth multi-method** (phone/2FA/magic-link/OAuth; `Profile.phone`).
- **Налаштування** sub-tabs (portal-security + WS admin-settings: шаблони/SMTP/брендинг/номенклатура/крони).
- **Лояльність 5-tier** (додати `silver`), **Wallet top-up**, **Портал білінг recurring + invoice/PDF**, **Реферали-воронка**, **Leave/capacity**, **Онбординг-візард** (здебільшого frontend).
