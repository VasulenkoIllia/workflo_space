1. **Лендінг навмисно лише на `dev.workflo.space`.** У маси не пускаємо, поки не виконано технічний

## 1. Принципи (коротко з аналізу)

- Ранжування = корисність для людини + довіра. Сторінка має право існувати, лише якщо на ній є
  унікальне: кейс, ціна, схема, обмеження, досвід. Змінене ключове слово в шаблоні — не привід.
- Ліди дають сторінки «низу воронки» (послуга, ціна, порівняння, інтеграція X↔Y), а не загальні
  статті «що таке AI» — їх зʼїдають AI-відповіді Google.
- Малі сайти з реальними цифрами (кейси, ціни «від») стоять у топі UA-видачі поруч з агенціями.
- Органіка — 6–12 місяців до відчутного результату; у перший рік основні клієнти — рекомендації,
  сайт має їх **переконувати** (кейси, ціни, процес, довіра).
- Мета на 6–9 міс після запуску: 25–35 глибоких сторінок, а не сотні тонких.

## 4. Контент — агенда окремого обговорення

Мета сесії — вирішити, **що і як ми говоримо на сайті**, щоб він приводив клієнтів, а не відштовхував.
Результат фіксуємо в `docs/LANDING_CONTENT_BRIEF.md`, тоді наповнюємо. До кожного пункту підготую
варіанти й рекомендацію.

1. **Кому продаємо.** Малий / середній бізнес UA? E-commerce, логістика, сервіси? EU-клієнти? Хто
   приносив гроші останні 1–2 роки — від цього головна обіцянка сайту.
2. **Бренд і подача.** «Ілля з Луцька» (особистий бренд, 1 людина) чи студія / команда з партнерами?
   Від цього — «Про мене», партнери, тон.
3. **Термінал-естетика vs зрозумілість.** `cwd`, `man ~/services`, `cat feedback.log` — «свої» для
   технарів, але власник магазину може не зрозуміти, що йому пропонують. Варіант: лишити стиль, але
   тексти й заголовки — мовою результату для бізнесу. Перевірка: 5-секундний тест на 3–5 реальних
   клієнтах («що тут пропонують і що мені робити далі?»).
4. **Послуги.** Чи правильні ці 4; що продається найбільше; чого не беремо; чи виділяти Telegram-ботів
   окремою послугою (найбільший попит у видачі).
5. **Ціни.** Показувати «від» чи ні; пакети; формат (фікс / погодинно / підтримка щомісяця).
   Орієнтири ринку: бот 3–8 тис. грн у масовому сегменті, агенції — від $1 800.
6. **Кейси — блокер запуску.** Які з 4 поточних реальні? Метрики підтверджені? Що можна з назвою
   клієнта, що анонімно? Вигадані кейси / відгуки / партнери на живому сайті — ризик довіри й
   порушення правил Google. Кейс Workflo («beta Q3 2026, 240+ waitlist») — оновити або прибрати.
7. **1С / BAS.** Кейсів і сторінок міграції не робимо (§0). Що з наявними згадками (послуга
   «Інтеграції», кейс №1, вибір у формі): прибрати, замінити на нейтральне «облікова система / ERP»
   чи лишити?
8. **Партнери.** Реальні люди з макета чи ні; чи потрібні профілі `/partners/*` взагалі.
9. **Довіра.** Фото, ФОП / юрособа, договір, гарантії, процес роботи, строки відповіді; зовнішні
   відгуки (Clutch / GoodFirms); чи є очні зустрічі в Луцьку (від цього — Google Business Profile).
10. **Заклик до дії.** Форма, Telegram, дзвінок, бронювання слоту в календарі? Хто і як швидко
    відповідає?
11. **Блог.** Чи пишемо регулярно (1–2 / міс), хто пише, чи AI-чернетка з обовʼязковою правкою; теми —
    реальні питання клієнтів.
12. **Галузеві та інтеграційні сторінки.** Список сценаріїв, де **вже є досвід**, — лише з них робимо
    сторінки (`/solutions`, `/integrations`).
13. **EN-версія.** Шукаємо клієнтів з EU зараз чи пізніше; які сторінки перекладаємо.
14. **Реклама.** Чи плануємо, бюджет, коли — від цього шаблон `/lp`.

## 6. Відкриті рішення власника (крім агенди §4)

- **Веб-аналітика:** GA4 (безкоштовно, звʼязка з GSC і Google Ads; для EU потрібен cookie-банер зі
  згодою) чи cookieless-аналітика (Plausible / Umami self-host — без банера, простіше, але без
  звʼязки з Ads). Рекомендація: GSC обовʼязково + cookieless для старту; GA4 — коли буде реклама.
- **Коли запуск** — після фаз 1–3; дату ставить власник.

## 7. Чекліст запуску (коли вирішите)

- [ ] Контент погоджено за брифом; кейси й партнери реальні; юр-тексти звірені
- [ ] DNS-запис `www` (редирект у Traefik уже є) → `https://www.workflo.space` віддає 301; HTTPS
- [ ] На проді немає `X-Robots-Tag: noindex`; на dev — лишається
- [ ] `robots.txt` і `sitemap.xml` на проді віддають 200 з правильним доменом
- [ ] GSC: надіслати sitemap, перевірити головну й послуги через «Перевірка URL», Rich Results Test
- [ ] Аналітика: подія «лід» доходить; UTM зберігаються в лідах
- [ ] Lighthouse ≥ 90 на головній, послузі, кейсі, статті
- [ ] 404 / 500 брендовані; немає посилань на dev-домени (`NEXT_PUBLIC_API_URL` на проді — прод-API)

## 8. Чого не робимо

- CMS-конструктор сторінок.
- Сотні шаблонних сторінок під міста / галузі / варіанти запиту без унікального вмісту.
- Сторінки й кейси міграції з 1С / BAS.
- Рекламні лендінги, відкриті для індексації.
- Купівлю посилань, фейкові відгуки / згадки, «AI-хаки» під відповіді Google.
- Російськомовну версію.

## 9. Метрики (після запуску)

- Головна: **ліди з органіки** (за сторінкою входу) + відповіді «звідки дізналися».
- Search Console: небрендові покази й кліки на послугах / кейсах / інтеграціях (фільтр брендових запитів).
- Оцінювати не раніше ніж через 6 місяців після запуску.

## 10. Пізніше: автоматизація (обговорити через 1–2 міс після запуску)

Ідея власника (27.09): агент / MCP, що стежить за GitHub, синхронізує дані з лендінгом, перевіряє
рекламу й правит SEO. Висновок на зараз — **не будуємо**, повертаємось, коли буде що міряти.

- **GitHub → лендінг — ні.** Клієнтські репозиторії під NDA, коміти клієнтів не переконують, а
  автоматично згенеровані з них сторінки = тонкий контент. Кращий сировинний матеріал для кейсів —
  закриті замовлення в самому workflo (клієнт, строки, результат).
- **Звіт + пропозиції — так, після запуску.** Щомісячний запланований агент: Search Console +
  аналітика + ліди з workflo → звіт і чернетки змін (PR у `apps/landing` або чернетка кейсу / статті в
  CMS). Застосовує людина; сам агент нічого не публікує й не змінює в рекламі.
- **Власний MCP — лише для власних даних.** Для GitHub, Search Console, GA4 і Google Ads вже є готові
  MCP-сервери. Своє має сенс тільки як MCP до workflo API (ліди, CMS-чернетки) — і, можливо, як фіча
  для SaaS-клієнтів (S14).
- **Реклама** — лише коли її запустимо; автозміни ставок і бюджетів без людини не робимо.
